# Приёмка группового проекта

Одна отправка, одна приёмка и один общий результат на команду до четырёх человек. Представлять работу и отвечать может любой участник; присутствующие могут дополнять. Индивидуальных оценок, нормы коммитов и отдельных защит нет.

До отправки прогоните `bash ci-scripts/test.sh`, сделайте commit и push в `develop`. После отправки версия замораживается. Проверяющий работает с чистой копией именно отправленного commit. Сданную копию на встрече не исправляют.

## Что происходит на встрече

| Время | Действие |
|---|---|
| 5 минут | Уточнить состав команды и отправленную версию, сверить инструменты |
| 5 минут | Линтер, проверка банка и общий контрольный прогон |
| 15 минут | Показать сессию, выбор вопросов, остановку и объяснение |
| 15 минут | Обсудить четыре собственных вопроса, по одному каждого типа |
| 15 минут | Обсудить передачу данных между модулями и вклад команды |
| 5 минут | Проверяющий фиксирует один общий результат на платформе |

Каждый слот рассчитан на один час. В плане дня 4 есть два слота: своя приёмка и проверка чужой работы выбранным пиром. Для команд с разными представителями они могут идти параллельно. При работе одному — последовательно. Оба слота входят в предел двадцати часов.

Проверяющий получает новое контрольное число сам:

```sh
python3 src/partner/examiner.py --control
```

Затем подставляет напечатанное число вместо `КЛЮЧ`:

```sh
python3 src/partner/examiner.py --control КЛЮЧ src/main.py datasets/
```

Это те же четыре этапа с другими начальными числами, без новых скрытых критериев. Дополнительно без конкретной причины повторять `--run` не нужно.

## Что нужно объяснить

Покажите, какие ответы изменили выбор следующего вопроса, почему программа остановилась и как посчитала уверенность. Объясните отличие проверки на идеальных собеседниках от оценки живого человека. Тесту не нужно правильно определить уровень проверяющего, чтобы проект был принят.

У выбранных собственных вопросов объясните правильный ответ, требуемое действие и назначенный уровень. Для `output` покажите фрагмент и ожидаемый вывод. Готовые 100 вопросов сохраняются; ревизия исходного банка не проводится.

Вместо отчёта по ролям покажите код, историю Git и передачу данных между загрузкой, проверкой ответа, алгоритмом и диалогом. Расскажите об одной общей сборке и о том, как исправили проблему на стыке частей. Отдельных доказательных файлов или письменных обоснований не требуется.

Публичная рубрика содержит [25 критериев](scoring_rus.md), объединённых в пять блоков. Оценка блока — число выполненных пунктов от 0 до 5. Полное выполнение — 25 из 25, бонусной части нет. Итоговый порог зачёта, если он нужен площадке, задаётся в её настройках и объявляется до старта.

Техническая неисправность площадки не считается учебной ошибкой команды. Спор разбирают по конкретному запуску, коду или вопросу. Результат на платформе фиксирует проверяющий; команда не готовит для этого дополнительные отчёты.
