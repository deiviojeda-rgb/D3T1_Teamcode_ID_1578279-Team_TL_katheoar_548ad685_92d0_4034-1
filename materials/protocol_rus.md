# Форматы и функции проекта v5

README задаёт цель и критерии результата. Здесь собраны точные форматы, чтобы части команды соединялись и их мог проверить готовый проверяющий. Python 3.10 или новее, только стандартная библиотека. Версию Python на станциях площадка фиксирует до начала проекта.

## 1 Банк вопросов

Папка содержит `bank_reference.txt`, `answers_reference.txt`, `bank_additional.txt`, `answers_additional.txt`, `bank_team.txt`, `answers_team.txt` и каталог `snippets`. Две первые пары — 100 готовых вопросов; последние два файла — ваши 20. Сохраните все готовые вопросы, ответы и фрагменты без изменений.

Файлы текстовые, UTF-8. Пустые строки и строки, начинающиеся после пробелов с `#`, пропускаются. Одна запись занимает одну строку. Разделитель — вертикальная черта `|`; пробелы по краям полей удаляются. Внутри значения вертикальная черта не используется.

У вопроса **пять полей**:

```text
id | тема | уровень | тип | текст
1000 | ввод | 1 | one | Какая функция читает строку с клавиатуры?
```

ID — уникальное положительное целое, у команды от 1000. Темы: `ввод`, `данные`, `ошибки`, `структура`. Уровень — целое 1–5. Тип — `one`, `many`, `short` или `output`. Все поля непустые. Длину банка и диапазоны готовых ID в загрузчик не зашивайте.

У ответа **четыре поля**:

```text
id | метка | верный | текст
1000 | А | 1 | input
1000 | Б | 0 | print
```

`верный` равен 1 или 0. Для `one` и `many` метки — кириллические `А`, `Б`, `В`, `Г`, `Д`, без повторов в одном вопросе; вариантов от двух до пяти. У `one` ровно один верный, у `many` не меньше двух, возможно все.

Для `short` метка `-`, все строки помечены 1. Каждая строка — принимаемая форма правильного ответа. Для `output` строк в файле ответов нет: код хранится в `snippets/<id>.py`, ожидаемый вывод — в `snippets/<id>.out`. Эталонный вывод содержит ровно одну непустую строку, завершающий перевод строки допустим. Программа читает код как текст, не исполняет его.

Ответы находятся в той же паре файлов, что и вопрос. Файлы команды до начала работы могут содержать только комментарии. В маленьком банке корректные дополнительные пары могут быть пустыми или отсутствовать; загрузчик считает их пустыми. Основной `bank_reference.txt` должен существовать. Пустой основной файл допустим.

Обработка повреждённых записей не является обязательной частью реализации. Проверяющий `--bank-check` отдельно проверяет корректность ваших данных до сессии. На отсутствующую папку или основной файл программа сообщает понятную ошибку запуска в stderr и завершается с ненулевым кодом.

## 2 Границы между модулями

`bank.load(folder)` возвращает словарь:

```python
{"questions": [], "total": 0}
```

`questions` — список всех вопросов, `total` — их количество. Дополнительные ключи разрешены. Каждый вопрос представлен так:

```python
{"id": 1000, "topic": "ввод", "level": 1, "type": "one",
 "text": "Какая функция читает строку с клавиатуры?",
 "options": [{"label": "А", "correct": True, "text": "input"},
             {"label": "Б", "correct": False, "text": "print"}],
 "code": "", "expected": ""}
```

Порядок `options` соответствует файлу. У `short` это принимаемые формы с `label="-"` и `correct=True`. У `output` список пуст, `code` и `expected` содержат тексты файлов фрагмента и вывода.

`answers.check(question, answer)` возвращает строку `верно`, `неверно` или `не принят`. Заготовка `bank.check(question, answer)` уже вызывает эту функцию: этот общий вход нужен проверяющему. Владелец загрузки работает в `bank.py`, владелец проверки ответов — в `answers.py`.

`engine.start()` создаёт новый независимый словарь состояния знаний для одной сессии. Значения должны быть совместимы с JSON: числа без NaN и Infinity, строки, bool, None, списки и словари со строковыми ключами.

`engine.observe(state, question, result)` изменяет состояние на месте и возвращает None. При `result="не принят"` весь словарь остаётся без изменений, в том числе после предыдущих принятых ответов. При верном или неверном ответе обновление задаёт команда.

Бюджет вопросов, показанные ID и генератор случайности храните отдельно от состояния знаний: попытка может быть израсходована без новых сведений о знаниях. `bank.py`, `answers.py` и `engine.py` не печатают; выводом занимается `main.py`. Программа не импортирует реализацию из `src/partner/`.

Функции выбора вопроса, остановки, вердикта и уверенности согласуйте до параллельной работы. Их имена и аргументы не предписаны. Готового алгоритма в заготовках нет.

## 3 Правила проверки ответа

`answer` — строка без завершающего перевода строки или None при конце ввода.

| Тип | Как сравнивать |
|---|---|
| Все | None, пустая строка и одни пробелы дают «не принят» |
| `one` | Удалить пробелы по краям, перевести метку в верхний регистр. Допустима одна известная метка. Неизвестная метка или несколько токенов дают «не принят» |
| `many` | Метки через пробелы, регистр верхний. Порядок и повторы не важны. Неизвестная метка даёт «не принят». Нужен точный набор всех правильных меток, частичный набор неверен |
| `short` | `strip` и `lower`, затем сравнение со всеми принимаемыми формами. Непустой ошибочный ответ — «неверно» |
| `output` | `strip` ответа и эталона, затем точное сравнение. Внутренние пробелы важны. Непустой ошибочный ответ — «неверно» |

Повторного ввода для того же вопроса нет. Любой показанный вопрос расходует одну из двадцати попыток и больше не показывается. При EOF сессия завершается сразу.

## 4 Команда запуска

```sh
python3 src/main.py ПАПКА [--scan] [--seed ЦЕЛОЕ] [--explain]
```

Запуск из корня репозитория. `--scan` несовместим с `--seed` и `--explain`. Неизвестные аргументы, отсутствие обязательного пути или неправильное число дают понятное сообщение в stderr и ненулевой код. При штатной сессии, включая EOF и пустой банк, код завершения 0.

`--seed` — начальное число для воспроизводимого выбора. При одинаковых коде, банке, Python, seed и ответах stdout и stderr должны совпадать. Случайный выбор разрешён, но не обязателен: полностью детерминированное решение тоже может игнорировать seed и быть воспроизводимым.

## 5 Сводка банка

`--scan` печатает только следующие строки в указанном порядке. Буквы заменяются количествами:

```text
всего | N
уровень 1 | L1
уровень 2 | L2
уровень 3 | L3
уровень 4 | L4
уровень 5 | L5
тема ввод | T1
тема данные | T2
тема ошибки | T3
тема структура | T4
тип one | K1
тип many | K2
тип short | K3
тип output | K4
```

Числа неотрицательные, каждая из сумм по уровням, темам и типам равна N. В конце один перевод строки, пустых строк нет. Вывод показывает программа; переносить его в документ не нужно.

## 6 Диалог в stdout

stdout — обычный вывод, который видит отвечающий. Сначала текст вопроса с префиксом `> `, затем варианты `one`/`many` в порядке файла или строки кода `output`. Отступы и пустые строки внутри кода сохраняются после префикса. У `short` вариантов нет. Пример:

```text
> Какая функция читает строку с клавиатуры?
> А) input
> Б) print
ОТВЕТ:
```

`ОТВЕТ:` — отдельная строка без префикса, после неё читается одна строка stdin. Печатайте её с `flush=True`, чтобы проверяющий увидел приглашение сразу. Если текст `ОТВЕТ:` встречается в коде вопроса, он показывается как `> ОТВЕТ:` и не считается приглашением.

Дополнительные заголовки между вопросами не печатайте. Последняя строка stdout — ровно один вердикт:

```text
УРОВЕНЬ 3 | ВОПРОСОВ 3 | УВЕРЕННОСТЬ 0.75
```

или:

```text
НЕ ОПРЕДЕЛЁН | ВОПРОСОВ 1 | УВЕРЕННОСТЬ 0.00
```

Количество — 0–20, уверенность — 0.00–1.00, ровно два знака и десятичная точка. Значения в примерах иллюстративные; формула не предписана. Без принятых ответов требуется «не определён» и 0.00. После вердикта пустой строки нет.

## 7 Автоматический журнал в stderr

stderr — отдельный служебный поток. Сюда программа сама печатает события с `flush=True`. Создавать файл журнала не нужно.

Перед вопросом:

```text
1 | вопрос 1000 | уровень 1 | тема ввод | тип one
```

После ответа:

```text
1 | ответ "А" | верно | дальше уровень 2
```

Номер шага начинается с 1. Ответ кодируется `json.dumps(answer, ensure_ascii=False)`: это сохраняет кавычки и различие между пустой строкой `""` и EOF `null`. Статус — один из трёх. Решение — `уровень 1`…`уровень 5` либо `стоп`. При выборе следующего вопроса заранее уровень можно указать точно; при выборе целевого уровня фактический следующий вопрос может отличаться, если вопросы нужного уровня закончились. Правило замены объясняет команда.

После последнего ответа решение — `стоп`. В конце ровно одна строка причины:

```text
стоп | причина сошлось
```

Причины и приоритет: `конец ввода` → `сошлось` → `бюджет` → `вопросов нет`. «Сошлось» означает, что выполнено выбранное командой правило достаточности ответов. «Бюджет» — показаны 20 вопросов, правило ещё не выполнено. У пустого банка до первого вопроса причина «вопросов нет». При EOF показанный вопрос получает ответ null, статус «не принят», решение «стоп» и учитывается в количестве.

## 8 Объяснение результата

Флаг `--explain` не меняет stdout и не меняет ход теста. После вердикта он добавляет в stderr строки с префиксом `ОБЪЯСНЕНИЕ:`. Без флага их нет. Текст свободный, но содержит:

- фактические ответы этой сессии и их влияние на оценку;
- итоговый уровень или причину неопределённости;
- фактическую причину остановки;
- смысл и расчёт уверенности, замеченные противоречия, если они были.

Заранее угадать противоречие, которое не встретилось среди заданных вопросов, не требуется. Учебная уверенность не выдаётся за подтверждённую вероятность. Письменный отчёт об алгоритме не сдаётся — объяснение формирует программа, а команда обсуждает его на приёмке.
